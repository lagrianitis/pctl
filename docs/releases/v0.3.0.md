## Overview

`pctl` can now fetch a JWT from an OAuth 2.0 provider, not only from Microsoft Graph.
`pctl oauth token` is for machines, trading a client id and secret for a token.
`pctl oauth login` is for people, opening the browser for a login and returning a token for
the user who signed in.

Every setting is a flag and an environment variable, the flag winning, so a token can be
fetched with nothing but the command line or with nothing but the environment. No tenant,
client or audience is built in.

## Added

- **`pctl oauth token`** — the client credentials grant. Fetches an access token for a
  machine, masked by default, with `--raw` to print only the token for a header and
  `--decode` to read its claims without verifying the signature. A valid token is cached
  until it expires, keyed on the provider, client, audience and scope and never on the
  secret, so repeated calls make one request.
- **`pctl oauth login`** — the authorization code flow with PKCE. Opens the provider's login
  page and exchanges the code for a user token. With a loopback redirect such as
  `http://127.0.0.1:8765/callback`, `pctl` catches the browser's return itself. With any other
  registered redirect, you copy the address from the browser and paste it at the prompt, or
  paste just the code. Nothing is written to disk: the token is not cached and no refresh
  token is kept.
- **Every setting as a flag and a variable** — `--issuer`, `--token-url`, `--authorize-url`,
  `--client-id`, `--client-secret`, `--audience`, `--scope`, `--redirect-uri`,
  `--login-timeout`, `--secret-id`, `--secret-region` and `--no-token-cache`, each with an
  environment variable behind it. A flag overrides its variable.
- **Endpoints from the issuer** — with `--issuer`, the token endpoint is
  `<issuer>/oauth/token` and the authorize endpoint is `<issuer>/authorize`, with no request
  made to find them. `--token-url` and `--authorize-url` override either.
- **Aliases** — `auth` and `auth0` reach `oauth`.
- **A wiki page** — `OAuth`, linked from the sidebar and Home, published with this release.

## Notes

- **`--client-secret` is a flag, deliberately.** It is the only secret flag in `pctl`, and it
  exists so every `oauth` setting works both ways. A flag is saved in shell history and is
  visible in the process list, so prefer `OAUTH_CLIENT_SECRET` or `--secret-id`, which reads
  `client_id` and `client_secret` from an AWS Secrets Manager secret. `azure` still has no
  such flag. The value is never printed, logged or written to the cache.
- **The issuer follows Auth0's layout.** A provider that lays its URLs out differently, such
  as Okta or Keycloak, is reached by giving `--token-url` and, for `login`, `--authorize-url`.
- **`oauth token` does not ask for `openid` scopes by default.** `oauth login` defaults to
  `openid profile email`. Pass `--scope` to change either.
- **A pasted login depends on the page you land on.** If the registered redirect is a hosted
  page, it may clear the authorization code from the address bar before you can copy it. The
  code is still in the browser's network log, in the redirect response. The code is valid
  only briefly, and an address from an earlier attempt is refused because its `state` does
  not match.
- **A rejected credential, a refused login or an unreachable provider exits 3.** Missing or
  unusable configuration exits 2, before anything is sent.
- **No new dependencies and no new permissions.** `httpx` and `click` already carried
  everything, and the token request is a plain form post.
- Requires Python 3.14 or newer, unchanged from v0.2.0.
