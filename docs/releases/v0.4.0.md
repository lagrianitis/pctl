# 🚀 v0.4.0 – App credentials

## Overview

`pctl azure apps` can now show the credentials of an app registration and when they expire,
and create and remove client secrets. Given an app by app ID or display name,
`apps get-client-secrets` lists its client secrets and certificates, how many days each has
left, and whether it has lapsed. It can also fail when one is close, so a pipeline can catch
an expiring secret before it breaks the application that uses it.

`apps add-client-secret` creates a secret and keeps its value, which Graph shows only once,
in an AWS Secrets Manager secret. `apps remove-client-secret` removes one, by key ID.

Listing is read-only and shows metadata only. Graph never returns the value of an existing
secret. The two writes need `Application.ReadWrite.All` or `Directory.ReadWrite.All`.

## Added

- **`pctl azure apps get-client-secrets`** — lists the client secrets and certificates of one app
  registration: type, display name, key ID, start and end date, and the hint for a secret.
  The app is named with `--app-id`, which skips the display name search, or `--app-name`,
  which accepts `--match exact | prefix | search`. Give one of the two. An ambiguous name is
  refused rather than guessed.
- **Expiry at a glance** — each credential shows the days it has left and a status of
  `valid`, `expiring` or `expired`. `--expiring-within DAYS` sets the window that counts as
  expiring.
- **A check you can script** — `--fail-on-expiry` still lists every credential, then exits
  **6** if any has expired or is expiring, so a pipeline can fail ahead of an outage.
- **Exit code 6** — a new code for a check that ran and said no, distinct from 5, where the
  provider failed before there was an answer. It is added to the exit-code tables in the
  README and on the wiki.
- **`pctl azure apps add-client-secret`** — creates a client secret on an app registration.
  `--store-in SECRET_ID` adds three keys to an existing Secrets Manager JSON secret and keeps
  every other key: `<app>_<name>_client_id` (the `appId`), `<app>_<name>_client_secret` (the
  new value) and `<app>_<name>_client_exp_date` (when it stops working, as Graph reports it).
  `--show-secret` prints the value once instead, or as well. `--valid-for-days` is 180 by
  default and at most 365. `--overwrite` replaces keys the secret already has.
- **A value that cannot be lost** — the command refuses to run with neither `--store-in` nor
  `--show-secret`, checks the destination before the secret exists, refuses a name the app
  already uses, and removes the new secret again if storing it fails. It is never retried
  after a server error or a dropped connection, since that could leave two live secrets.
- **`pctl azure apps remove-client-secret`** — removes one client secret, named by
  `--key-id` and never by name. A secret that has expired or ends within 30 days is removed
  as asked. One with more time left, or no end date, needs `--force`.
- **`--app-name` and `--app-id`** — all three commands name the app with one of the two.
  `--app-id` takes the `appId` and does no display name search; `--app-name` takes the display
  name and honours `--match`.

## Notes

- **Listing never shows a secret value.** Graph returns a name, a key ID, a short hint and the
  dates for an existing secret, and the value only once, at creation. `add-client-secret` is
  the one place that value is handled: it is shown only with `--show-secret`, stored only
  where `--store-in` names, and kept out of every report, log and error message.
- **`add-client-secret` is not idempotent.** Each run makes a new secret, so a name the app
  already uses is refused. After an unknown outcome, look at `get-client-secrets` before
  running it again.
- **`remove-client-secret` cannot be undone**, and removes the secret from the app only. A
  copy in Secrets Manager is not touched. Certificates cannot be removed: Graph asks for proof
  of possession.
- **Renamed from the working names.** The commands are `get-client-secrets`,
  `add-client-secret` and `remove-client-secret`. `get-client-secrets` also lists
  certificates.
- **AWS permissions for `--store-in`:** `secretsmanager:DescribeSecret`, `GetSecretValue` and
  `PutSecretValue` on the target secret. AWS credentials come from the usual chain.
- **Object IDs are not accepted** by these three commands, only the `appId` or the display
  name.
- **Dates are UTC.** They are shown as Graph reports them, in ISO 8601, and the days remaining
  are whole days measured from the moment the command runs.
- **An app with no credentials is not a failure.** It exits 0 and says so on stderr.
- **Only app registrations.** Service principals can hold credentials of their own, and a
  tenant-wide scan for expiring credentials is not part of this release.
- **Permissions:** `get-client-secrets` needs the same as `apps get`, `Application.Read.All`
  or `Directory.Read.All`, according to the Graph documentation. The two writes need
  `Application.ReadWrite.All` or `Directory.ReadWrite.All`. Not confirmed against a real
  tenant.
- **Not confirmed against a real tenant or AWS account.** The Graph response fields, the
  permissions above and a real Secrets Manager write were taken from documentation and
  tested against fakes (respx for Graph, moto for Secrets Manager). `add-client-secret` has
  not been run against a real tenant, so the first real run is best done on a throwaway app
  registration and a scratch Secrets Manager secret.
- **A credential with no end date** is `unknown` and never fails the check, because there is
  nothing to judge it by.
- **`daysRemaining` is rounded down.** Zero means under a day left, and a lapsed credential
  is negative.
- Requires Python 3.14 or newer, unchanged from v0.3.0.
