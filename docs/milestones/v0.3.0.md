# Overview

Give `pctl` a way to fetch a JWT from an OAuth 2.0 provider: client credentials for
machines, and a browser login for people. Until now the only tokens `pctl` could produce
were for Microsoft Graph, which meant that calling any other API behind Auth0 started with
a hand-written request, or a one-off script kept outside the repository.

The question that started it was the second of those: two small scripts, one per flow, each
with the tenant, client and audience written into the source. This milestone turns them
into commands that take every one of those as a setting, so nothing about a tenant lives in
the code.

For the Engineering Portfolio this is the second test of the **case → service → action**
shape. A new provider is a new case package and one entry in a table, and nothing that
already works is reshaped. `oauth` has no services, only two case-level actions like
`azure token`, which the structure was already designed to allow.

It is also where one of the project's security rules gets an explicit exception. Secrets
have stayed out of argv since v0.1.0. Here the owner chose to accept `--client-secret` so
every setting works both as a flag and as an environment variable, with the flag winning.
The exception is recorded in `security.md`, confined to `oauth`, and the flag's help text
steers people to the variable instead.

Documentation as Code continues: the commands, their settings and the two ways back from
the browser are documented in the README and on a new wiki page, published with the
release.

---

# Objectives

- Get a machine token from a client ID and secret in one command, without a hand-written
  request.
- Get a user token through a browser login, including for clients whose registered redirect
  is a page `pctl` cannot listen on.
- Accept every parameter as a flag as well as an environment variable, with the flag
  winning, the client secret included.
- Keep the token masked unless it is explicitly asked for, and never write a user token or a
  refresh token to disk.
- Keep every tenant, client and audience out of the source, defaults included.
- Reuse what already exists rather than copy it: the token cache, the Secrets Manager
  loader and the masking and decoding of a JWT.

# Success Criteria

- `pctl oauth token` returns an access token from a client credentials request, exits 3 when
  the provider rejects the credentials, and exits 2 before sending anything when the client
  id, the secret or the provider is missing.
- `pctl oauth login` completes a PKCE login by a loopback redirect and by a pasted address,
  refuses a redirect whose `state` does not match, and exits 3 when the provider refuses.
- For every setting, a flag overrides the matching environment variable.
- With `--issuer`, the endpoints are `<issuer>/oauth/token` and `<issuer>/authorize`, with no
  request made to find them, and an explicit URL wins over both.
- The token is masked unless `--raw` is passed, and the client secret is never printed,
  logged, written to the cache or included in `repr`.
- A second `oauth token` within the token's lifetime makes no request, and `oauth login`
  writes nothing to the cache.
- No tenant, client id, audience or secret appears anywhere in the source as a default.
- `pctl --help` imports none of boto3, botocore, httpx, uvloop or h2, with the new command
  paths added to `LAZY_PATHS`.
- `uv run ruff check .` and `ruff format --check .` clean, and `uv run pytest -n auto` green
  with **zero warnings**, needing no tenant, no AWS account and no network.
- A real login against the provider this was written for returns a token by pasted address,
  with the client whose registered redirect is a hosted page.
