# Overview

Ship the first working version of `pctl`: one command-line tool that reads from more
than one cloud provider behind a single, predictable interface. Two providers land here,
Microsoft Graph and AWS DynamoDB, and the shape they establish is what every later
provider follows rather than renegotiates.

For the Engineering Portfolio this milestone is the reference example of a small tool
built to production standards rather than demo standards: a real packaging story, real
CI, a documented exit-code contract, credentials that never touch argv or disk, and
tests that need no cloud account to run.

It follows Documentation as Code throughout. The README, the test conventions, the
engineering rules, the issue and pull request templates, the release-notes template and
the delivery plan all live in the repository, version alongside the code they describe,
and change only through the same reviewed pull requests. Nothing authoritative lives in
a wiki or a ticket.

---

# Objectives

- Establish the `case → service → action` command shape and mirror it in the source
  tree, so adding a provider means adding a package rather than reshaping what works.
- Ship two provider cases end to end: Microsoft Graph tokens and groups, and DynamoDB
  table metadata and item reads.
- Keep the tool fast enough to sit inside a shell loop: lazy imports, an on-disk token
  cache, page prefetching and server-side payload narrowing.
- Make the output machine-readable by default, with streaming formats, a clean
  stdout/stderr split and a documented exit-code contract that CI jobs can branch on.
- Keep every credential out of argv, out of config files and out of the repository,
  resolving from the environment, AWS Secrets Manager or the provider's own chain.

# Deliverables

## Repository

- `src/pctl` package: root group, lazy dispatch, app context, renderer, error types,
  token cache and secret resolution.
- `azure` case: Graph transport with retries and pagination, the `token` and `raw`
  actions, and the `groups` service (`list`, `get`, `members`).
- `aws` case: DynamoDB transport with segmented parallel scan, plus `tables`,
  `describe`, `scan`, `query` and `get`.
- `pyproject.toml` and a committed `uv.lock`, with hatchling packaging `src/pctl` into
  the wheel and test tooling confined to PEP 735 dependency groups.
- `.github/workflows/ci.yml`: ruff lint and format on every push, the full suite on
  pull requests, and version-checked tagging on published releases.
- Three pytest tiers mirroring the package layout: `unit` for pure functions, `smoke` for
  the CLI surface, `e2e` for the real command path with only the provider boundary faked.
  All collected, so `uv run pytest` is the whole suite.

## Documentation Layer

- `README.md`: install, configure, usage per case, output formats, exit codes, layout,
  performance rationale and security notes.
- `src/test/smoke/README.md`: test tier conventions and the two mistakes that cost time.
- `.kiro/steering/`: product, structure, tech stack, code style, engineering principles,
  git, security and workflow rules, plus the commit, PR, issue and release procedures.
- Issue and pull request templates for both GitHub and GitLab, kept in sync.
- `docs/templates/release-notes.md` and `docs/plans/v0.1.0-pr-plan.md`.

## Generated Artifacts _(Optional)_

- `pctl` wheel built by hatchling from `src/pctl`.
- The `v0.1.0` annotated tag, created by the CI `tag` job rather than by hand.
- `docs/releases/v0.1.0.md`, the release notes published with the GitHub release.

# Success Criteria

- Every pull request merged to `main` green on `lint` and, from the second onward, on
  `test`. Planned as five, delivered as three: the two provider cases and the cross-case
  tier had to land together, because `smoke/test_cli_surface.py` enumerates the whole
  command tree.
- `pctl --help` renders without importing `boto3`, `botocore`, `httpx`, `uvloop` or
  `h2`, enforced by a test rather than by convention.
- Both pytest tiers pass with zero warnings and require no credentials, no tenant and no
  AWS account.
- The exit-code contract is documented in the README and covered by tests: 0, 1, 2, 3,
  4, 5, 130, 141.
- No credential, secret or employer-identifying value reaches the public remote, and an
  app-only install (`uv sync --no-dev`) pulls exactly four runtime dependencies.
- `v0.1.0` is tagged by CI, with the tag verified against `[project].version` in
  `pyproject.toml`.
