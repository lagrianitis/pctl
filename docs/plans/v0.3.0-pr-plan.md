### Review notes

**A new case with no services.** `oauth` has two case-level actions, like `azure token` and
`azure raw`. There is nothing to list or get, so inventing a service level would only add
a directory.

**`--client-secret` is a flag, on purpose.** Every other secret in `pctl` stays out of argv.
Here the owner chose to accept the flag so each setting works both ways, and the exception
is written into `security.md` before any code relies on it. It is confined to `oauth`, its
help text points at `OAUTH_CLIENT_SECRET` and `--secret-id`, and the value is kept out of
`repr`, output, logs and the cache key. Please review this one closely.

**The endpoints follow Auth0's layout, with no discovery.** `--issuer` gives
`<issuer>/oauth/token` and `<issuer>/authorize`. Discovery was written first and removed in
the last commit: it cost a request before every call to find a layout that was already
known. A provider with another layout is reached by giving `--token-url` and
`--authorize-url`, which win over the issuer.

**Two ways back from the browser.** A loopback redirect is caught by a listener that binds
`127.0.0.1` only, serves one path, and stops at the first request that carries parameters.
Any other redirect falls back to a prompt, because the client this was written for is
registered with a hosted callback page. A `state` that is present must match; a loopback
redirect without one is refused; only a hand-pasted code, which never saw the state, may
omit it.

**The listener skips `HTTPServer`'s reverse DNS lookup.** `HTTPServer.server_bind` calls
`getfqdn` on the host, which can stall for seconds even for `127.0.0.1`.

**Nothing from a user login touches the disk.** The token is never cached and the refresh
token is never kept. Machine tokens are cached the way `azure token` caches, keyed on
configuration and never on the secret, and a token with no lifetime is not reused.

**Synchronous `httpx`.** A token is one request. An event loop would add startup time and
buy nothing.

**`--login-timeout` has a floor of 0.1 seconds.** It exists so the timeout can be tested
without waiting.

### Description

```markdown
# Summary

Adds `pctl oauth`, which fetches a JWT from an OAuth 2.0 provider. `token` uses the client
credentials grant for machines and `login` opens a browser for the authorization code flow
with PKCE for people. Every setting is a flag and an environment variable, the flag
winning, so nothing about a tenant is built in.

## Changes

- Add the `oauth` case with `token` and `login`, and the aliases `auth` and `auth0`.
- Accept every setting as a flag with an environment variable behind it, the client secret
  included. This is a deliberate exception to the no-secret-flags rule, recorded in
  `security.md` and confined to `oauth`.
- Derive the endpoints from `--issuer` as `<issuer>/oauth/token` and `<issuer>/authorize`,
  with `--token-url` and `--authorize-url` overriding either.
- Catch a loopback redirect on `127.0.0.1`, or accept a pasted address or code for clients
  registered with a hosted callback page. Refuse a mismatched or missing `state`.
- Cache machine tokens like `azure token`. Never write a user token or a refresh token.
- Move JWT masking and decoding into `pctl.jwt`, and rename the Secrets Manager loader to
  `load_client_secret`, since `oauth` is the second caller of each.
- Document the commands in the README and on a new wiki page, and add placeholders to
  `.env.example`.
- Add the v0.3.0 milestone definition, release notes draft and this plan.
```
